# decisions.md — 設計判断の記録（ADR）

## ADR-001: UIフレームワークにMFCを採用

- **日付**：2026-06-21
- **状態**：採用
- **背景**：ツール自体をVS2022で作る際、C++/WinForms（存在しない）・WPF（C#のみ）・MFCの選択肢があった
- **決定内容**：C++ / MFC のダイアログベースアプリとして実装
- **却下した選択肢**：C#/WinForms → C++縛りのため却下。Win32 API直接 → UIコード量が膨大になるため却下
- **影響**：MFCのリソースエディタでUIを定義できる。VS2022のデザイナが使える

## ADR-002: タブ構成をフェーズ別に設計

- **日付**：2026-06-21
- **状態**：採用
- **背景**：スペック駆動のmdファイル（5種類）をどのようにUIに割り当てるか
- **決定内容**：フェーズ別タブ（要件定義／設計／タスク管理／CLAUDE.md）に分割
- **却下した選択肢**：mdファイル1枚=1タブ → ファイル数が多くUIが散漫になる
- **影響**：タブ4枚でmdファイル5種類をカバーする設計（設計タブにstructure+decisionsを統合）

## ADR-003: プラットフォーム選択をラジオボタンで実装

- **日付**：2026-06-21
- **状態**：採用
- **背景**：出力するmdの技術スタック欄がプラットフォームによって変わる
- **決定内容**：5種類（WinForms/WPF/MFC/Win32/Web）のラジオボタンで選択し、structure.mdの技術スタック欄を自動補完
- **却下した選択肢**：ドロップダウンリスト → 選択肢が一覧で見えるラジオボタンの方がUXが良い
- **影響**：CMdGeneratorがプラットフォーム種別に応じて異なるテンプレート文字列を使用する

## ADR-004: ファイル出力をUTF-8（BOMなし）で統一

- **日付**：2026-06-21
- **状態**：採用
- **背景**：生成したmdファイルをVS Code・GitHub・Claude Codeで使用する
- **決定内容**：UTF-8 BOMなしで出力（`CStdioFile` + `CP_UTF8` 変換）
- **却下した選択肢**：ShiftJIS → GitHubでの文字化けリスクがある。UTF-8 BOMあり → 一部ツールで互換性問題が出る
- **影響**：MFCのCStringからUTF-8バイト列への変換処理が必要（WideCharToMultiByte使用）
